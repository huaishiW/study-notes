# 7.1 关系模式与数据依赖

> 知识库入口：[数据库原理知识库](数据库原理知识库.md)

> 关联：本章用于判断和改进关系模式设计，候选码、主码、外码等概念会落到[关系完整性](02-关系数据库.md#2.3%20关系的完整性)和 [SQL 数据定义](03-关系数据库标准语言SQL.md#3.1%20数据定义)中。

## 7.1.1 关系模式的形式化定义
关系模式可以表示为五元组：$R ( U, D, DOM, F )$
* 其中：
	- R：关系名
	- U：组成该关系的属性名集合
	- D：属性组 U 中属性所来自的域
	- DOM：属性向域的映像集合
	- F：属性间数据依赖关系的集合
## 7.1.2 数据依赖
* **定义**：属性之间相互依赖、相互制约的关系
* 关系模式中常见的数据依赖包括：函数依赖( FD )、多值依赖( MVD )
>数据库模式的好坏与关系中各属性之间的依赖关系密切相关。因此设计关系模式时，必须从语义上分析这些依赖关系。
## 7.1.3 函数依赖
### 7.1.3.1 函数依赖的定义
* 设 $R(U)$ 是属性集 U 上的关系模式，X 和 Y 是 U 的子集。
* 若对 $R(U)$ 的任意一个可能关系 r，都不可能存在两个元组在 X 上属性值相等而在 Y 上属性值不等，则称：
```
  X 函数确定 Y  
  Y 函数依赖于 X  
  记作 X -> Y
```
其中：
- X 称为该函数依赖的决定属性集或决定因素
- Y 是被决定的属性集
* **注意**：
	1. 函数依赖不是指某个具体关系实例偶然满足的约束，而是指关系模式的所有可能关系实例都必须满足的约束
	2. 函数依赖属于语义范畴，只能根据数据语义确定
	3. 数据库设计者可以根据现实世界规则作强制规定
### 7.1.3.2 平凡函数依赖与非平凡函数依赖
* 在关系模式 $R(U)$ 中，若 $X -> Y$ 且 Y 是 X 的子集，则称 $X -> Y$ 是平凡函数依赖。若 Y 不是 X 的子集，则称为非平凡函数依赖
>平凡函数依赖对任意关系模式都必然成立，通常不反映新的语义。因此若无特别说明，一般讨论非平凡函数依赖。
### 7.1.3.3 完全函数依赖与部分函数依赖
设 $X -> Y$
- 若对 X 的任意真子集 X'，都不存在 $X' -> Y$，则称 Y 完全函数依赖于 X
- 若存在 X 的某个真子集 X'，使得 $X' -> Y$ 成立，则称 Y 部分函数依赖于 X
>部分函数依赖通常出现在组合码场景中
### 7.1.3.4 传递函数依赖
* 若存在：$X -> Y$ 和 $Y -> Z$ 并且 Y 不函数确定 X，则称 Z 传递函数依赖于 X
### 7.1.3.5 码、候选码、主码、外码
* 设 K 为关系模式 $R<U, F>$ 中的属性或属性组合。若 K 能函数确定 U 中的全部属性，则 K 称为 R 的候选码
* 若一个关系模式有多个候选码，则可选定其中一个作为主码
* **相关概念**：
	- 候选码：能唯一标识元组的最小属性组
	- 主码：从候选码中选定用于标识元组的码
	- 主属性：包含在某个候选码中的属性
	- 非主属性：不包含在任何候选码中的属性
	- 全码：关系模式的全部属性共同构成候选码
	- 外码：某属性或属性组不是本关系的码，但它是另一个关系模式的码

>主码和外码共同提供了表示关系之间联系的手段
# 7.2 范式
* **定义**：符合某种规范化级别的关系模式集合。关系数据库中的关系必须满足一定要求，满足不同程度要求的关系模式属于不同范式
* 常见范式之间的关系大致为：$1NF -> 2NF -> 3NF -> BCNF -> 4NF$
>规范化程度越高，通常对数据依赖的限制越严格，冗余和异常越少
## 7.2.1 第一范式（1NF）
* **定义**：若关系 R 中每个属性都是不可再分的，并且每个属性都是单值的，则称 R 满足第一范式，记为：$R ∈ 1NF$
* 要求：
	- 属性不可再分：不能出现子属性
	- 属性值为单值：每个单元格中不允许出现多个数据

>1NF 是对关系的最低要求。不满足 1NF 的关系是非规范化关系
## 7.2.2 第二范式（2NF）
* 若关系模式 $R ∈ 1NF$，并且每一个非主属性都完全函数依赖于 R 的码，则：$R ∈ 2NF$
### 7.2.2.1 1NF关系中的主要问题
在 1NF 中，若存在非主属性对码的部分函数依赖，就会导致**冗余**、**插入异常**和**删除异常**
### 7.2.2.2 解决方法
通过模式分解，消除非主属性对码的部分函数依赖
>结论：若关系 R 的候选码是单属性，则 R 必定属于 2NF
## 7.2.3 第三范式（3NF）
* 关系模式 $R<U, F> ∈ 1NF$，若不存在码 X、属性组 Y 和非主属性 Z，使得：
```
  X -> Y  
  Y -> Z  
  Y 不函数确定 X
```
则称：$R<U, F> ∈ 3NF$
* 简单来说：3NF 要求非主属性不能传递依赖于候选码
### 7.2.3.1 2NF关系中的主要问题
达到 2NF 后，仍可能存在非主属性对码的传递函数依赖
### 7.2.3.2 解决方法
通过分解消除非主属性对码的传递函数依赖
### 7.2.3.3 3NF的性质
1. 若 $R ∈ 3NF$，则 R 的每个非主属性既不部分依赖于候选码，也不传递依赖于候选码
2. 若 $R ∈ 3NF$，则 $R ∈ 2NF$
3. 将 2NF 关系分解为多个 3NF 关系，可以在一定程度上解决插入异常、删除异常、数据冗余和修改复杂等问题
4. 但 3NF 不能完全消除所有异常和冗余
>结论：若关系 R 的所有属性都是主属性，则 R 必定属于 3NF
## 7.2.4 BCNF
* 关系模式 $R<U, F> ∈ 1NF$，如果对 R 的每个非平凡函数依赖：$X -> Y$
 只要 Y 不属于 X，则 X 必含有候选码，那么：$R ∈ BCNF$
* 简单来说：每一个决定属性集都必须包含候选码
### 3NF与BCNF的关系
- 若 $R ∈ BCNF$，则必有 $R ∈ 3NF$
- 若 $R ∈ 3NF$，不一定有 $R ∈ BCNF$
- 若 $R ∈ 3NF$ 且只有一个候选码，则 R 必属于 BCNF
- 任何二元关系模式必定属于 BCNF
* 3NF 的“**不彻底**”体现在：可能还存在主属性对码的部分依赖或传递依赖
>若一个数据库模式中的所有关系模式都属于 BCNF，则在函数依赖范畴内已经实现了较彻底的分离，消除了由函数依赖导致的插入和删除异常
## 7.2.5 多值依赖
函数依赖主要表达属性间的一对一或多对一联系，但无法表达多对多联系。
* 一般地，属性间关系可分为：
	- 若 X 和 Y 是一对一联系，则存在 $X -> Y$ 和 $Y -> X$
	- 若 X 和 Y 是多对一联系，则存在 $X -> Y$，但不存在 $Y -> X$
	- 若 X 和 Y 是多对多联系，则 X 与 Y 之间通常不存在函数依赖
* 多值依赖用于描述某些**多对多联系中**相互独立的多值事实
### 7.2.5.1 多值依赖的定义
设 $R(U)$ 是属性集 U 上的关系模式，X、Y、Z 是 U 的子集，并且：$Z = U - X - Y$
若对 R 的任一关系 r，r 在 $(X, Z)$ 上的每个值对应一组 Y 的值，且这组 Y 的值仅决定于 X，与 Z 无关，则称：
```
  X 多值确定 Y  
  Y 多值依赖于 X  
  记作 X ->> Y
```
### 7.2.5.2 多值依赖的等价定义
* 在 $R(U)$ 的任一关系 r 中，如果存在元组 t、s，满足：$t[X] = s[X]$ 则必然存在元组 w、v，使得：
```
  w[X] = v[X] = t[X] = s[X]
  w[Y] = t[Y], w[Z] = s[Z]
  v[Y] = s[Y], v[Z] = t[Z]
```
即交换两个元组的 Y 值后得到的新元组也必须存在于关系中，则称：$X ->> Y$
### 7.2.5.3 多值依赖与函数依赖的区别
1. 多值依赖的有效性与属性集范围有关。 若 $X ->> Y$ 在 U 上成立，则在 W 上不一定成立；反之也不一定成立
2. 多值依赖不仅涉及 X 和 Y，还涉及 U 中的其余属性 Z
3. 函数依赖只与 X、Y 有关。若 $X -> Y$ 在 R(U) 上成立，则在任意包含 X 和 Y 的属性集上都成立
4. 若函数依赖 $X -> Y$ 成立，则对任意 Y' 属于 Y，都有 $X -> Y'$ 成立。 但若多值依赖 $X ->> Y$ 成立，不能断言对任意 Y' 属于 Y 都有 $X ->> Y'$ 成立
## 7.2.6 第四范式（4NF）
* 关系模式 $R<U, F> ∈ 1NF$，如果对于 R 的每个非平凡多值依赖：$X ->> Y$ 只要该多值依赖不是函数依赖，X 都必须含有候选码，则：$R ∈ 4NF$
>4NF 不允许存在“非平凡且非函数依赖”的多值依赖。
* 特点：
	- 若 $R ∈ 4NF$，则 $R ∈ BCNF$
	- 如果只考虑函数依赖，BCNF 已经是较高规范化程度
	- 如果同时考虑多值依赖，则 4NF 是更高规范化程度
# 7.3 数据依赖的公理系统
## 7.3.1 逻辑蕴含与闭包
* 对于满足函数依赖集合 F 的关系模式 $R<U, F>$，若其任何一个关系 r 中函数依赖 $X -> Y$ 都成立，则称：F 逻辑蕴含 $X -> Y$
* 在关系模式 $R<U, F>$ 中，由 F 所逻辑蕴含的函数依赖全体称为 F 的闭包，记为：F+
* F+ 包括：
	- F 本身
	- 由 F 推出的非平凡函数依赖
	- 由 F 推出的平凡函数依赖
## 7.3.2 Armstrong公理系统
* 对关系模式 $R<U, F>$，有以下推理规则：
	1. 自反律：若 Y 属于 X，且 X 属于 U，则：$X -> Y$。自反律可以得到平凡函数依赖，不依赖于 F
	2. 增广律：若 $X -> Y$，且 Z 属于 U，则： $XZ -> YZ$
	3. 传递律：若：$X -> Y,\;Y -> Z$ 则：$X -> Z$
## 7.3.3 属性集闭包
### 7.3.3.1 属性集闭包的定义
* 设 F 为属性集 U 上的一组函数依赖，X 属于 U。$XF+ = \{ A | X -> A\;能由\;F\;根据 \;Armstron\;公理导出 \}$，XF+ 称为属性集 X 关于函数依赖集 F 的闭包
* 用途：判断 $X -> Y$ 是否能由 F 导出，等价于判断 Y 是否属于 XF+
### 7.3.3.2 如何确定候选码
* 若**没有给出函数依赖集**，应根据实际语义确定码和函数依赖集
* 若**给出函数依赖集**，可按以下思路：
	- 能唯一标识元组的属性或属性组就是候选码
	- 不出现在任何函数依赖右部的属性，通常必须包含在候选码中
	- 完整判断时，需要计算属性集闭包，若某属性组闭包等于全部属性集 U，则它是超码；若其任意真子集都不是超码，则它是候选码
## 7.3.4 函数依赖集等价
* 若 $F+ = G+$ 则称函数依赖集 F 与 G 等价，也可称 F 覆盖 G，或 G 覆盖 F。
* 引理：$F+ = G+$ 的充分必要条件是 F 属于 G+ 且 G 属于 F+
* 在实际判断中：
	- 对 F 中每个函数依赖 $X -> Y$，判断 Y 是否属于 XG+
	- 对 G 中每个函数依赖 $X -> Y$，判断 Y 是否属于 XF+
	* 若两边都成立，则 F 与 G 等价
## 7.3.5 最小依赖集
若函数依赖集 F 满足以下条件，则称 F 为极小函数依赖集
1. F 中任一函数依赖的右部只含有一个属性
2. F 中不存在冗余函数依赖。即不存在某个 $X -> A$，使得去掉它后仍与原 F 等价
3. F 中每个函数依赖左部不存在冗余属性。即不存在 X 的真子集 Z，可用 $Z -> A$ 替代 $X -> A$ 并保持等价
# 7.4 模式分解
把低一级范式的关系模式分解为若干高一级范式的关系模式，方法并不唯一。只有能够保证分解后的关系模式与原关系模式等价，分解才有意义
* 模式分解的等价要求包括：
	1. 分解具有无损连接性
	2. 分解保持函数依赖
	3. 分解既具有无损连接性，又保持函数依赖

>这些也是关系模式分解的重要原则。
## 7.4.1 模式分解定义
* 关系模式 $R<U, F>$ 的一个分解可表示为：$ρ = \{R1<U1, F1>, R2<U2, F2>, ..., Rn<Un, Fn>\}$要求：$U = U1 ∪ U2 ∪ ... ∪ Un$ 且不存在某个 Ui 被另一个 Uj 包含
## 7.4.2 函数依赖在属性集上的投影
* 函数依赖集合：$\{X -> Y | X -> Y 属于 F+ 且 XY 属于 Ui\}$ 的一个覆盖 F<sub>i</sub>，称为 F 在属性集 U<sub>i</sub> 上的投影
## 7.4.3 无损连接性
* 设：$ρ = \{R1<U1, F1>, R2<U2, F2>, ..., Rk<Uk, Fk>\}$ 是 $R<U, F>$ 的一个分解若对 $R<U, F>$ 的任何一个关系 r，都有：$r = mρ(r)$ 其中 $mρ(r)$ 是 r 在分解后各关系模式上的投影的自然连接，则称分解 ρ 具有无损连接性
>无损连接性保证分解后再连接不会丢失信息，也不会产生伪元组
## 7.4.4 保持函数依赖
* 若：$F+ = (F1 ∪ F2 ∪ ... ∪ Fn)+$ 则称分解 ρ 保持函数依赖
>保持函数依赖意味着原关系模式中的约束可以在分解后的各关系中直接检查，不必通过连接后再检查
## 7.4.5 无损连接性与保持函数依赖的关系
* 二者是互相独立的标准：
	- 具有无损连接性的分解不一定保持函数依赖
	- 保持函数依赖的分解不一定具有无损连接性
* 进一步说明：
	- 若分解具有无损连接性，则能保证不丢失信息
	- 若分解保持函数依赖，则有助于减轻或解决异常
	- 若分解既具有无损连接性又保持函数依赖，则既不丢失信息，又能较好地维护约束，是较理想的分解
	- 保持函数依赖并具有无损连接性的分解通常可达到 3NF，但不一定能达到 BCNF
