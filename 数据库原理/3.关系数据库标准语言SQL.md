# 3.1 数据定义

> 知识库入口：[数据库原理知识库](数据库原理知识库.md)

> 关联：SQL 是[关系模型](2.关系数据库.md)的标准语言，查询语句会被转换为关系代数表达式并进入[查询处理和查询优化](4.关系查询处理和查询优化.md)流程。

## 3.1.1 模式（schema）
* **定义**：是一个**命名空间**，在这个空间中可以进一步定义该模式包含的数据库对象，例如基本表、视图、索引等
>引用模式，为了解决数据库对象太多不好管理的缺点
* 现代关系数据库管理系统提供了一个层次化的数据库对象命名机制
	* 一个关系数据库管理系统的实例( Instance )中可以建立多个数据库
	* 一个数据库中可以建立多个模式
	* 一个模式下通常包括多个表、视图和索引等数据库对象
## 3.1.2 定义和删除模式
``` sql
create schema <模式名> authorization <用户名> --创建模式,不填模式名则为用户名
drop schema <模式名> <cascade | restrict>    --删除模式
```
* 执行以上命令必须要 DBA 权限，或者具有 create schema 权限
* **cascade**：默认为此等级，代表删除此模式时，将模式下的所有表和视图一起删除
* **restrict**：删除模式时，若模式下还有表和视图则无法删除该模式，需要先将模式下的表和视图删除
>**注意**：SQL 中的"<>"代表该项必须填充，”[]“代表该项为选填项
## 3.1.3 定义和删除基本表
``` sql
create table <表名>(
		<列名> <数据类型>[ <列级完整性约束条件> ]
		[，<列名> <数据类型>[ <列级完整性约束条件>] ] …
		[，<表级完整性约束条件> ]
)[表约束条件];
drop table <表名> [restrict | cascade] --默认等级为restrict
```
* **表名**：所要定义的基本表的名字
* **列名**：组成该表的各个属性(列)
* **列级完整性约束条件**：涉及对应属性列的完整性约束条件
* **表级完整性约束条件**：涉及一个或多个属性列的完整性约束条件
* **表约束条件**：对整个表的约束条件
* 数据类型：

| 类型           | 描述                 |
| ------------ | ------------------ |
| char( n )    | 长度为 n 的定长字符串       |
| varchar( n ) | 最大长度为 n 的变长字符串     |
| int          | 全字长二进制整数           |
| smallint     | 半字长二进制整数           |
| float        | 双字长浮点数             |
| date         | 日期型，格式为 YYYY-MM-DD |
| time         | 时间型，格式为 HH.MM.SS   |
| timestamp    | 日期加时间              |
| clob         | 文本大对象              |
| blob         | 二进制大对象             |

>**注意**：不同的DBMS支持的数据类型不完全相同
## 3.1.4 修改和删除基本表
``` sql
alter table <表名>
  [ add [column] <新列名> <数据类型> [ 完整性约束 ] ]
  [ add <表级完整性约束>]
  [ drop [column] <列名> [cascade | restrict ] ] --默认等级为cascade
  [ drop constraint <完整性约束名> [cascade | restrict ]] --默认等级为cascade
  [ alter column <列名> <数据类型> ]；
```
* **add** 子句：**增加**新列和新的完整性约束条件
* **drop** 子句：**删除**指定列和完整性约束条件
* **alter column** 子句：用于**修改**数据类型，若要修改完整性约束要遵循”先删除，后添加“
>**注意**：修改列名的语句，不同 DBMS 不一致
## 3.1.5 建立和删除索引
* 建立索引是加快查询速度的有效手段，但建立索引是根据需要而定的
* 部分 DBMS 会在含有 primary key (主键)和 unique (唯一键)这两个完整性约束的列上自动建立索引
* 索引的维护和使用一般是由 DBMS 自动完成，但是在很多时候还是需要 DBA 的干预，才可以提高数据库的整体性能
``` sql
create [unique] [cluster] index <索引名> on <表名>(<列名>[<次序>][,<列名>[<次序>] ]…);
drop index <索引名>; --删除时，系统会从数据字典中删去有关该索引的描述
```
* **unique** ：表明此索引的每一个索引值只对应唯一的数据记录，即列中由 unique 完整性约束
* **cluster** ：表明要建立的索引是聚簇索引
* 索引可以建立在表的**一列或多列**上，各列名之间用逗号分隔
* **次序**：指定索引值的排列次序，升序：ASC，降序：DESC。不填时默认：ASC
# 3.2 数据查询
## 3.2.1 查询语句
``` sql
select [all | distinct] <目标列表达式> [, <目标列表达式>]...
from <查询对象表达式> -- 可以为表、视图、派生表、子查询结果等
[ where <条件表达式> ]
[ group by <列名> [ having <条件表达式>] ]
[ order by <列名> [asc | desc] ]
```
* **select** 子句：指定要显示的属性列，**distinct** 代表查询结果去重，默认值为 **all** 不去重。<目标列表达式> 可以是字符串常量、函数、列别名或算术表达式等
* **from** 子句：指定查询对象
* **where** 子句：指定查询条件，作用于基表或视图，从中选择满足条件的元组
* **group by** 子句：对查询结果按指定列的值分组，该属性列值相等的元组为一个组。通常会在每组中作用集函数。
* **having** 短语：筛选出只有满足指定条件的组，必须跟在 group by 子句后在分组完成之后起作用，作用于组
* **order by** 子句：对查询结果表按一个或者多个指定的列值进行升序或降序排序
## 3.2.2 常用查询条件
| 查询条件 | 谓词                                           |
| :--- | :------------------------------------------- |
| 比较   | =, >, <, >=, <=, !=, <>, !, !<；not + 上述比较运算符 |
| 确定范围 | between and，not between and                  |
| 确定集合 | in 在集合中，not in 不在集合中                         |
| 字符匹配 | like，not like                                |
| 空值   | is null，is not null                          |
| 多重条件 | and，or                                       |
* and 优先级高于 or 并且可以使用括号改变优先级
* between and 的查询范围是闭区间，not between and的查询范围是开区间
* 涉及空值的查询需要在 where 子句中使用 is null 或者是 is not null
### 模糊匹配
``` sql
[not] like '<匹配模板>' [escape '<换码字符>']
```
* **匹配模板**：固定字符串或者含通配符的字符串
* **两种通配符**：“%”代表任意长度的字符串；“\_”代表任意单个字符，汉字也是一个字符
>**注意**：当用户要查询的字符串本身就含有“%”或“\_”时，要使用 escape '<换码字符>' 短语对通配符进行转义，换码字符最好为除“%”或“\_”的任意字符
## 3.2.3 聚合函数
| 聚合函数    | 功能描述             | 通用 sql 语法示例                                                                            | 关键注意点                                                  |
| :------ | :--------------- | :------------------------------------------------------------------------------------- | :----------------------------------------------------- |
| count() | 统计行数或指定列中非空值的个数。 | count( \* ) (统计所有行，含 null )<br>count( 列名 ) (统计非空值)<br>count( distinct 列名 ) (统计去重后的非空值) | count( \* ) 与 count( 1 ) 性能几乎相同；count( 列名 ) 会忽略 null 值 |
| sum()   | 计算指定数值列的总和。      | sum( 列名 )<br>sum( distinct 列名 )                                                        | 只能用于数值类型的列；会忽略 null 值(视为 0 处理)                         |
| avg()   | 计算指定数值列的平均值。     | avg( 列名 )<br>avg( distinct 列名 )                                                        | 只能用于数值类型；会忽略 null 值(分母不统计空值行)                          |
| max()   | 获取指定列的最大值。       | max( 列名 )                                                                              | 适用于数值、日期、字符串(按字典序)；会忽略 null                            |
| min()   | 获取指定列的最小值。       | min( 列名 )                                                                              | 适用于数值、日期、字符串；会忽略 null                                  |

* 聚集函数可以在目标列表达式、where 子句、having 短语中使用
## 3.2.4 连接查询
* **定义**：同时涉及多个表的查询，可以使用比较运算符或者标准连接语法作为其连接条件
* 在连接查询时，需要给每一个表取一个**表别名**方便使用。此外设置表别名之后在此SQL语句中只能使用别名代表这个表。同一个表可以引用两次并给他们分别取不同的名字
### 3.2.4.1 内连接（inner join）
- **核心逻辑**：只返回两个表中**满足连接条件**( ON 子句)的行。如果某一行在另一个表中没有匹配项，则**直接丢弃**，不会出现在结果中
- **SQL 特征**：不匹配的字段不会补 NULL ，直接消失
- **语法**：
``` sql
select * from 表A A别名 inner join 表B B别名 on A别名.关联字段 = B别名.关联字段;
-- 通常 INNER 可以省略，直接写 JOIN 默认就是内连接
```
### 3.2.4.2 外连接（outer join）
- **核心逻辑**：返回**一个表(或两个表)的全部行**，即使它在另一个表中没有匹配项。对于没有匹配到的字段，用 NULL 填充
* 外连接分为 **3 种**：

| 类型       | 关键字        | 核心规则                         | 通俗讲法                    |
| -------- | ---------- | ---------------------------- | ----------------------- |
| **左外连接** | left join  | 保住**左表**(left 关键字左边的表)的全部行   | 左边的表是老大，无论如何都要显示出来      |
| **右外连接** | right join | 保住**右表**( right 关键字右边的表)的全部行 | 右边的表是老大，无论如何都要显示出来      |
| **全外连接** | full join  | 保住**两个表**的全部行                | 两边都是老大，不管匹不匹配，所有人的数据都留着 |
* 左外连接语法：
``` sql
select * from 表A A别名 left join 表B B别名 on A别名.关联字段 = B别名.关联字段;
-- 通常 INNER 可以省略，直接写 JOIN 默认就是内连接
```
>**注意**：在使用时一般情况下不使用右外连接，而是选择将两个表的顺序调换之后使用左外连接。全外连接很少使用并且部分 DBMS 不原生支持全外连接
## 3.2.5 嵌套查询（子查询）
* **定义**：将一个查询块嵌套在另一个查询块的 where 子句或 having 短语的条件中的查询
* 查询块：一个完整的 select-from-where 语句
### 3.2.5.1 两类执行逻辑
- **不相关子查询（独立子查询)**：
    - **执行顺序**：**先内后外**。内层查询只执行一次，得出结果集后交给外层使用
    - **特点**：内层查询可以独立运行
- **相关子查询（依赖子查询)**：
    - **执行顺序**：**由外向内循环**。外层每取出一行数据，就把这行的某个值传给内层查询，内层根据这个值查一遍，然后把结果返回给外层判断
    - **特点**：内层查询不能独立运行(引用外层的列)。性能通常较慢，因为相当于“嵌套循环”
### 3.2.5.2 四个核心谓词
- **in（属于)**：判断外层值是否在子查询返回的**列表**中。不相关子查询居多，谓词前后的字段必须是匹配的
- **any/some（任一)**：与比较运算符连用，只要满足子查询中**任意一个**值即可
- **all（所有)**：与比较运算符连用，必须满足子查询中**所有**值
- **exists（存在)**：判断子查询**是否有数据返回**。只要有 1 条就返回真( True )，否则假( False )。**几乎总是相关子查询**。它不关心返回什么值，只关心有没有行
>由 exists 引出的子查询，其目标列表达式通常都用 * ，因为带 exists 的子查询只返回真值或假值，给出列名无实际意义
* 所有带 in 谓词、比较运算符、any 和 all 谓词的子查询都能用带 exists 谓词的子查询等价替换。但是部分带 exists 或 not exists 谓词的子查询不能被其他形式的子查询等价替换
### 3.2.5.3 any和all与聚合函数的对应关系

|     | =          | !=         | <    | <=    | >     | \>=    |
| --- | ---------- | ---------- | ---- | ----- | ----- | ------ |
| any | in         | 永真(除非单个元素) | <max | <=max | \>max | \>=min |
| all | 永假(除非单个元素) | not in     | <max | <=min | \>max | \>=max |
## 3.2.6 集合查询
* 解释：就是**把两个 select 查询的结果当成两个集合进行运算**
* 主要包括**并**( union )、**交**( intersect ) 和**差**( except ) 三种运算
>**注意**：参与集合运算的两个查询必须具有相同的列数，并且对应列的数据类型要兼容
### 3.2.6.1 并查询（union）
* **作用**：把两个查询结果合并在一起，并**自动去除重复记录**
``` sql
select ... from ...
union
select ... from ...
```
* 如果不想去重则使用：union all 此语句比 union 执行速度快
### 3.2.6.2 交查询
* **作用**：查询两个结果中**共同拥有**的数据，并返回共同拥有的数据
``` sql
select ... from ...
intersect
select ... from ...
```
### 3.2.6.3 差查询
* **作用**：查询**只属于第一个集合，而不属于第二个集合的数据**
``` sql
select ... from ...
except
select ... from ...
```
### 3.2.6.4 对比连接查询和集合查询
- **join（连接)**：根据共同属性把两个**关系组合起来**，得到一个新的、更宽的**关系**(列变多)
- **union、intersect、except（集合运算)**：要求两个关系具有相同的结构，对它们进行**集合层面的运算**(行变多、变少或取公共部分)
# 3.3 数据更新
## 3.3.1 插入数据
``` sql 
insert into <表名> [(<属性列1>[，<属性列2>…)]
values (<常量1> [，<常量2>] … )
-- 也可以将 values子句 替换为 子查询语句
```
* **功能**：将新元组插入指定表中
* **into** 子句：指定要插入数据的表名及属性列，且属性列的顺序可与表中的顺序不一致
	* **没有指定属性列**：表示要插入的是一条完整的元组，且属性列属性与表定义中的顺序一致
	* **指定部分属性列**：插入的元组在其余属性列上取空值
* **values** 子句：提供的值必须与 into 子句匹配，包括值的个数和类型，使用 select 进行子查询插入时也必须匹配
## 3.3.2 修改数据
``` sql
update <列名>
set <列名>=<表达式>[，<列名>=<表达式>]…
[where <条件>]
```
* **功能**：修改指定表中满足 where 子句条件的元组
* **set** 子句：指定修改方式(可以为各种表达式)、要修改的列、修改后取值
* **where** 子句：指定要修改的元组，若无 where 子句表示要修改表中的所有元组
## 3.3.3 删除数据
``` sql
delete from <表名>
[where <条件>]
```
* **功能**：删除指定表中满足 where 子句条件的元组
* **where** 子句：指定要删除的元组，若无 where 子句表示要删除表中的所有元组
## 3.3.4 空值处理
* **定义**：指“不知道”或“不存在”或“无意义”的值。具有不确定性，不是具体的值，是一个标志
* 在创建表时，可以使用 **not null** 约束某列不能有空值
* 空值可以由**数据更新**、**外连接**、**空值的算数运算**产生
>注意：空值与任何值(包括空值)的**算术运算结果**为空值，**比较运算结果**为unknown
# 3.4 视图
* **定义**：是由一个或多个基本表(也可以包含其他视图)通过 select 查询定义出来的虚拟表
* 创建视图本质上是为了简化我们的查询，可以将常用的查询语句保存起来达到快速查询的目的，并且它**一般不保存数据**
## 3.4.1 视图的特点
1. 视图是**虚拟表**，只保存查询定义。而普通表真正储存数据
2. 数据全部来自基本表，并且可以让其中的数据根据基本表数据的变化而变化
3. 视图一般不独立存储数据，因此占用空间很小。但部分 DBMS 也支持物化视图，物化视图之后它将会真正保存查询结果
4. 可以像一般表一样使用查询语句查询其中的数据
5. 部分视图可以更新，指可以通过视图修改数据
## 3.4.2 视图的作用
1. **简化查询**：可以把复杂查询封装起来
2. **提高安全性**：通过视图可以隐藏敏感数据
3. **统一接口**：提供统一的数据访问接口
4. **提高数据复用性**
## 3.4.3 基本语法
### 3.4.3.1 创建视图
``` sql
create view <视图名> as
select ...
from ...
where ...;
```
### 3.4.3.2 删除视图
``` sql
drop view <视图名>
```
### 3.4.3.3 修改视图（不同的DBMS有不同）
``` sql
create or replace view <视图名> as 
select ...
from ...
where ...;
```
* 此外，对视图中的数据可以像普通表一样进行查询，而增删改操作只有部分视图支持
