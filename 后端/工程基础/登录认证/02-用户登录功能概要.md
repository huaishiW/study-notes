# 1. 登录功能的需求

登录页面中，用户输入：

```text
用户名
密码
```

然后点击登录按钮。

前端会向服务端发送登录请求，服务端根据用户提交的用户名和密码判断身份是否合法。

如果用户名和密码正确：

> 登录成功，并返回用户相关信息。

如果用户名或密码错误：

> 登录失败，并返回错误信息。

# 2. 登录功能的本质

材料中对登录功能进行了一个很直接的总结：

> 登录功能本质上是一次查询。

也就是：

> 根据用户名和密码查询员工信息。

如果能够查询到员工：

> 说明用户名和密码匹配，登录成功。

如果查询不到：

> 说明用户名或密码错误，登录失败。

# 3. 登录接口基本信息

当前登录接口的请求路径为：

```text
/login
```

请求方式：

```text
POST
```

请求参数使用 JSON 格式，例如：

```json
{
  "username": "admin",
  "password": "123456"
}
```

登录成功后，服务端返回的主要数据包括：

- 员工 ID
    
- 用户名
    
- 姓名
    
- token
    

不过在基础登录阶段，`token` 暂时为空，后续 JWT 登录认证中再补充生成逻辑。

# 4. LoginInfo 登录结果封装类

为了封装登录成功之后返回给前端的数据，材料中定义了：

```java
LoginInfo
```

代码如下：

```java
@Data
@NoArgsConstructor
@AllArgsConstructor
public class LoginInfo {

    private Integer id;
    private String username;
    private String name;
    private String token;

}
```

各字段含义如下：

|字段|含义|
|---|---|
|`id`|员工 ID|
|`username`|用户名|
|`name`|员工姓名|
|`token`|登录认证令牌|

在当前基础登录阶段：

```java
token
```

暂时还没有真正生成。

# 5. LoginController

材料中定义了：

```java
LoginController
```

负责接收登录请求。

示例代码：

```java
@Slf4j
@RestController
public class LoginController {

    @Autowired
    private EmpService empService;

    @PostMapping("/login")
    public Result login(@RequestBody Emp emp) {

        log.info("员工来登录啦 , {}", emp);

        LoginInfo loginInfo = empService.login(emp);

        if (loginInfo != null) {
            return Result.success(loginInfo);
        }

        return Result.error("用户名或密码错误~");
    }
}
```

# 6. @PostMapping("/login")

```java
@PostMapping("/login")
```

表示：

> 当前方法用于处理 `/login` 路径的 POST 请求。

因此前端发送：

```text
POST /login
```

时，就会进入：

```java
login()
```

方法。

# 7. @RequestBody 接收登录参数

Controller 方法参数：

```java
@RequestBody Emp emp
```

表示：

> 将请求体中的 JSON 数据转换成 `Emp` 对象。

例如前端发送：

```json
{
  "username": "admin",
  "password": "123456"
}
```

Spring 会把其中的数据封装到：

```java
Emp emp
```

对象中。

然后就可以将这个对象继续传递到 Service 层。

# 8. Controller 的主要职责

`LoginController` 主要完成：

1. 接收登录请求。
    
2. 获取用户提交的用户名和密码。
    
3. 调用 Service 完成登录判断。
    
4. 根据 Service 返回结果决定登录成功还是失败。
    
5. 将最终结果响应给前端。
    

Controller 本身并不直接访问数据库。

具体的登录业务判断继续交给：

```java
EmpService
```

处理。

# 9. EmpService 定义登录方法

在：

```java
EmpService
```

接口中增加：

```java
LoginInfo login(Emp emp);
```

完整形式：

```java
/**
 * 登录
 */
LoginInfo login(Emp emp);
```

这个方法接收：

```java
Emp
```

对象，其中包含用户名和密码。

返回值为：

```java
LoginInfo
```

如果登录成功：

> 返回登录用户信息。

如果登录失败：

> 返回 `null`。

# 10. EmpServiceImpl 实现登录业务

材料中的基础实现如下：

```java
@Override
public LoginInfo login(Emp emp) {

    Emp empLogin = empMapper.getUsernameAndPassword(emp);

    if (empLogin != null) {

        LoginInfo loginInfo = new LoginInfo(
                empLogin.getId(),
                empLogin.getUsername(),
                empLogin.getName(),
                null
        );

        return loginInfo;
    }

    return null;
}
```

# 11. Service 中的登录判断

首先调用：

```java
empMapper.getUsernameAndPassword(emp);
```

根据用户名和密码查询员工信息。

查询结果保存在：

```java
Emp empLogin
```

中。

如果：

```java
empLogin != null
```

说明数据库中存在同时匹配用户名和密码的员工。

因此：

> 登录成功。

如果：

```java
empLogin == null
```

说明没有匹配到员工。

因此：

> 登录失败。

# 12. 登录成功后封装 LoginInfo

登录成功后，并不是直接把完整的：

```java
Emp
```

对象返回给前端。

而是重新构建：

```java
LoginInfo
```

例如：

```java
LoginInfo loginInfo = new LoginInfo(
        empLogin.getId(),
        empLogin.getUsername(),
        empLogin.getName(),
        null
);
```

只返回登录后真正需要的数据：

- ID
    
- 用户名
    
- 姓名
    
- Token
    

当前阶段 Token 暂时设置为：

```java
null
```

后续再通过 JWT 生成真正令牌。

# 13. EmpMapper 根据用户名和密码查询

在 Mapper 中定义：

```java
Emp getUsernameAndPassword(Emp emp);
```

并使用：

```java
@Select
```

编写 SQL：

```java
@Select("""
        select *
        from emp
        where username = #{username}
          and password = #{password}
        """)
Emp getUsernameAndPassword(Emp emp);
```

材料中的原始写法为：

```java
@Select("select * from emp where username = #{username} and password = #{password}")
Emp getUsernameAndPassword(Emp emp);
```

# 14. SQL 的判断逻辑

SQL：

```sql
select *
from emp
where username = #{username}
  and password = #{password}
```

要求两个条件同时满足：

```text
用户名正确
密码正确
```

才能查询出员工记录。

因此：

- 用户名正确，密码错误 → 查询不到
    
- 用户名错误，密码正确 → 查询不到
    
- 用户名和密码都正确 → 查询成功
    

这正好对应登录功能的判断逻辑。

# 15. 登录请求的完整调用链

一次登录请求中，各层职责可以这样理解。

## 15.1 Controller

```java
LoginController.login()
```

负责：

> 接收请求和返回响应。

## 15.2 Service

```java
EmpService.login()
```

负责：

> 处理登录业务逻辑。

## 15.3 Mapper

```java
EmpMapper.getUsernameAndPassword()
```

负责：

> 查询数据库。

## 15.4 LoginInfo

```java
LoginInfo
```

负责：

> 封装登录成功后返回给前端的数据。

因此整个登录功能保持了典型的分层结构。

# 16. 登录成功时的处理

如果：

```java
empMapper.getUsernameAndPassword(emp)
```

查询到了员工：

```java
empLogin != null
```

Service 返回：

```java
LoginInfo
```

Controller 接收到非空结果后：

```java
return Result.success(loginInfo);
```

最终前端获得登录成功的数据。

# 17. 登录失败时的处理

如果数据库中没有查询到符合条件的员工：

```java
empLogin == null
```

Service 返回：

```java
null
```

Controller 判断：

```java
if (loginInfo != null)
```

不成立，因此返回：

```java
Result.error("用户名或密码错误~");
```

这样前端就能够知道本次登录失败。

# 18. 为什么不直接返回 Emp

数据库中的：

```java
Emp
```

通常包含很多员工信息，例如：

- 密码
    
- 手机号
    
- 性别
    
- 薪资
    
- 部门
    
- 入职日期
    

登录接口并不需要把这些字段全部返回给前端。

因此材料专门定义：

```java
LoginInfo
```

只封装登录结果真正需要的数据。

这样也能够让：

> 数据库实体与接口响应数据保持不同职责。

# 19. 当前登录功能还缺少什么

当前实现已经能够完成：

> 用户名密码正确 → 登录成功  
> 用户名密码错误 → 登录失败

但是还有一个非常重要的问题：

> 登录成功后，后续请求仍然无法证明当前用户已经登录。

而且当前：

```java
LoginInfo.token
```

仍然是：

```java
null
```

因此，这只是：

**基础登录功能。**

后续还需要：

- 生成用户身份令牌
    
- 将令牌返回给前端
    
- 后续请求携带令牌
    
- 服务端统一校验令牌
    

材料也正是在完成基础登录之后，发现未登录仍然能够访问业务系统，从而继续引出了登录校验。

# 20. 当前阶段需要掌握的核心内容

1. 登录功能本质上是根据用户名和密码查询员工信息。
    
2. 登录接口路径为 `/login`，请求方式为 POST。
    
3. `@RequestBody` 可以将请求体中的 JSON 登录数据封装成 `Emp` 对象。
    
4. Controller 负责接收登录请求和返回登录结果。
    
5. Service 负责执行登录业务判断。
    
6. Mapper 负责根据用户名和密码查询数据库。
    
7. 查询到员工说明登录成功，查询不到说明登录失败。
    
8. `LoginInfo` 用于封装登录成功后返回给前端的数据。
    
9. 当前基础登录阶段的 `token` 暂时为空。
    
10. 登录成功后还需要进一步解决后续请求中的身份认证问题。
    

> [!tip] 一句话总结
> 
> `基础登录功能通过 Controller 接收用户名和密码，Service 调用 Mapper 查询员工信息，查询成功后封装 LoginInfo 返回前端，查询失败则返回用户名或密码错误。`
