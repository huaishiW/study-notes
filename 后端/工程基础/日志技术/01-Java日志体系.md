# 1. 什么是日志

程序中的日志用于记录应用程序运行过程中的各种信息。

常见内容包括：

- 程序运行信息。
    
- 程序状态信息。
    
- 数据处理过程。
    
- 错误信息。
    
- 异常信息。
    

可以把程序日志理解为：

> 程序运行过程中的记录信息，用于帮助开发人员了解程序在什么时候执行了什么操作、运行到了什么状态，以及是否出现了异常。

例如：

```java
log.info("开始查询用户信息");
```

可以记录程序正在执行查询操作。

如果程序发生异常，也可以通过日志记录错误信息，方便后续定位问题。

---

# 2. 为什么需要日志

在应用程序中记录日志，主要有以下几个目的。

## 2.1 追踪程序执行过程

程序运行过程中可能经过很多方法和业务步骤。

通过日志可以记录：

```text
请求进入
业务开始执行
数据库查询完成
业务处理完成
响应返回
```

当程序出现问题时，可以根据这些信息判断：

> 程序究竟执行到了哪一步。

---

## 2.2 追踪程序中的数据

程序执行过程中，经常需要观察某些重要数据。

例如：

```java
log.info("当前用户id: {}", userId);
```

通过日志可以帮助判断：

- 参数是否正确。
    
- 数据是否成功传递。
    
- 查询结果是否符合预期。
    

因此日志也是分析程序运行状态的重要工具。

---

## 2.3 排查程序问题

当应用程序出现错误时，只知道：

```text
程序出错了
```

通常并不足以定位问题。

如果有详细日志，就可以查看：

- 错误发生的时间。
    
- 错误发生的位置。
    
- 程序执行到哪一步。
    
- 当时传入了什么数据。
    
- 出现了什么异常。
    

因此日志对于：

> 定位问题和解决问题

非常重要。

---

## 2.4 监控系统运行状态

日志不仅可以用于开发阶段。

应用程序部署后，也可以通过日志观察：

- 系统是否正常运行。
    
- 哪些功能正在被调用。
    
- 是否频繁发生异常。
    
- 系统当前处于什么状态。
    

因此日志也是系统运行监控的重要信息来源。

---

## 2.5 辅助性能优化

通过记录程序执行过程和相关信息，可以帮助分析：

- 哪些操作耗时较长。
    
- 哪些业务执行频繁。
    
- 哪些环节可能存在性能问题。
    

然后进一步针对程序进行优化。

因此日志不仅用于：

> 查错误。

还可以用于了解整个应用程序的运行情况。

# 3. System.out.println() 能不能当日志使用

在学习 Java 初期，经常使用：

```java
System.out.println("开始执行");
```

观察程序执行过程。

例如：

```java
System.out.println("查询用户");
```

这种方式确实可以在控制台输出信息。

在简单测试程序中，它也非常方便。

但是在真正的应用程序中，如果大量使用：

```java
System.out.println(...)
```

作为日志，就会逐渐出现一些问题。

---

# 4. System.out.println() 存在的问题

## 4.1 日志代码被硬编码

例如：

```java
System.out.println("查询部门列表");
```

只要程序执行到这里，这条信息就会输出。

如果以后不希望输出，就只能：

- 删除代码。
    
- 注释代码。
    

也就是说：

> 无法方便地统一控制哪些日志输出、哪些日志不输出。

当项目中存在大量 `System.out.println()` 时，管理会非常困难。

---

## 4.2 只能简单输出到控制台

`System.out.println()` 最常见的作用就是向控制台输出内容。

但是实际应用程序中的日志可能需要：

- 输出到控制台。
    
- 保存到日志文件。
    
- 按日期生成日志。
    
- 根据级别决定是否输出。
    

简单的控制台打印无法方便地完成这些功能。

---

## 4.3 不利于扩展和维护

如果整个项目到处都是：

```java
System.out.println(...)
```

以后想统一调整日志行为时，需要修改大量 Java 代码。

例如希望：

> 开发环境输出详细信息，正式环境只输出重要信息。

单纯使用 `System.out.println()` 很难统一管理。

因此在实际项目中，一般不会将它作为正式的日志方案，而是使用专业的日志技术。

---

# 5. 为什么需要日志框架

日志是大量项目都会使用的通用功能。

如果每个项目都自己实现：

- 日志输出。
    
- 日志格式。
    
- 日志文件保存。
    
- 日志开关。
    
- 日志级别。
    

会产生大量重复工作。

因此 Java 中出现了专门处理日志的框架。

日志框架可以帮助应用程序：

> 以统一、可配置的方式记录和管理日志。

例如开发人员在 Java 代码中只需要：

```java
log.info("查询部门列表");
```

具体日志：

- 是否输出。
    
- 输出到哪里。
    
- 使用什么格式。
    

则可以由日志框架负责控制。

---

# 6. Java 中常见的日志技术

常见的日志相关技术包括：

- JUL
    
- Log4j
    
- Logback
    
- SLF4J
    

虽然它们都与日志有关，但它们并不完全属于同一种角色。

---

# 7. JUL

JUL 是 Java SE 平台提供的官方日志框架。

JUL 可以用于记录日志。

它的特点是：

- Java 官方提供。
    
- 配置相对简单。
    
- 可以完成基本日志功能。
    

但相对其他日志框架而言，其灵活性和性能表现并不突出。

因此在现代 Java 项目中，还会经常看到其他日志框架。

---

# 8. Log4j

Log4j 是 Java 中比较经典的日志框架。

它提供：

- 日志记录。
    
- 灵活配置。
    
- 多种日志输出目标。
    

也就是说，Log4j 不只是简单地：

```text
向控制台打印字符串
```

而是提供了更加完整的日志管理能力。

---

# 9. Logback

Logback 是一个常用的日志框架。

它可以真正负责：

> 日志的记录和输出。

例如：

```java
log.info("程序启动成功");
```

最终日志如何输出，通常需要底层日志框架进行处理。

Logback 支持通过配置文件控制：

- 日志格式。
    
- 输出位置。
    
- 日志级别。
    
- 控制台输出。
    
- 文件输出。
    

当前 Spring Boot 项目中也会使用到 Logback。

---

# 10. SLF4J

SLF4J 的全称是：

```text
Simple Logging Facade for Java
```

可以理解为：

> Java 简单日志门面。

SLF4J 提供了一套统一的日志操作接口和抽象。

它本身主要解决的问题是：

> 让 Java 程序使用统一的方式编写日志代码，而不用直接依赖某一种具体日志框架。

例如程序中可以统一写：

```java
log.info("用户登录成功");
```

至于真正负责日志输出的底层实现，可以由具体日志框架完成。

---

# 11. 为什么需要 SLF4J

假设程序直接使用某一个具体日志框架提供的 API。

那么 Java 代码就会直接依赖这个日志框架。

以后如果需要更换底层日志实现，就可能需要修改大量代码。

SLF4J 的作用就是：

> 在应用程序和具体日志框架之间提供统一的日志接口。

应用程序只面向 SLF4J 提供的日志 API 编程。

这样可以减少代码对具体日志实现的直接依赖。

---

# 12. SLF4J 与 Logback 的区别

这是理解 Java 日志体系时非常重要的一点。

可以分别理解：

## 12.1 SLF4J

主要负责：

> 定义统一的日志操作方式。

属于日志门面。

---

## 12.2 Logback

主要负责：

> 真正实现日志记录和日志输出。

属于具体日志框架。

因此：

> SLF4J 更像是一套统一接口，而 Logback 是这些接口背后的具体实现之一。

---

# 13. 日志门面是什么

“门面”可以理解为：

> 为应用程序提供统一入口。

例如程序希望记录日志：

```java
log.info("开始处理请求");
```

应用程序不需要关心底层到底使用：

- Logback
    
- Log4j
    
- 其他实现
    

只需要按照统一的日志 API 使用即可。

因此日志门面的作用就是：

> 隔离应用程序与具体日志实现。

---

# 14. 为什么日志体系中既有接口又有实现

这种设计与 Java 中常见的：

> 面向接口编程

思想类似。

如果应用程序直接绑定具体实现：

```text
应用程序 → Logback
```

程序和具体框架之间的依赖比较强。

增加日志门面后，可以理解为：

```text
应用程序 → SLF4J → 具体日志框架
```

其中：

- 应用程序使用统一日志接口。
    
- 具体日志框架完成真正的日志处理。
    

这样可以让日志使用方式更加统一。

---

# 15. 日志体系中的职责划分

几个常见概念可以这样区分：

|技术|主要角色|
|---|---|
|JUL|Java 官方日志框架|
|Log4j|具体日志框架|
|Logback|具体日志框架|
|SLF4J|日志门面、统一日志接口|

其中尤其需要注意：

> SLF4J 和 Logback 不能简单理解为两个竞争关系的日志框架。

它们承担的是不同角色。

通常可以组合使用：

```text
SLF4J + Logback
```

应用程序使用 SLF4J 提供的统一接口，而 Logback 负责底层日志实现。

---

# 16. Logger

Java 程序中通常通过：

```java
Logger
```

对象记录日志。

例如：

```java
private static final Logger log =
        LoggerFactory.getLogger(LogTest.class);
```

然后就可以使用：

```java
log.debug("开始计算...");
log.info("计算完成");
```

进行日志记录。

这里的 `Logger` 可以理解为：

> Java 程序记录日志时使用的日志对象。

---

# 17. LoggerFactory

示例中通过：

```java
LoggerFactory.getLogger(LogTest.class);
```

获取 `Logger`。

例如：

```java
private static final Logger log =
        LoggerFactory.getLogger(LogTest.class);
```

传入：

```java
LogTest.class
```

表示这个 Logger 与：

```java
LogTest
```

类关联。

因此输出日志时，可以知道：

> 这条日志来自哪个类。

---

# 18. 基本日志使用方式

可以定义：

```java
private static final Logger log =
        LoggerFactory.getLogger(LogTest.class);
```

然后使用：

```java
log.debug("开始计算...");
```

记录程序开始执行。

执行完成后：

```java
log.info("计算结果为: " + sum);
```

记录结果。

最后：

```java
log.debug("结束计算...");
```

记录程序执行结束。

这种方式相比：

```java
System.out.println(...)
```

最大的区别并不是代码短了多少，而是：

> 日志已经进入统一的日志体系，可以由日志框架进行配置和管理。

---

# 19. 日志中可以包含哪些信息

专业日志框架输出的内容通常不仅包括：

```text
日志正文
```

还可以包含其他运行信息，例如：

- 日志产生时间。
    
- 当前线程。
    
- 日志级别。
    
- 输出日志的类。
    
- 具体日志内容。
    

例如一条日志可能包含：

```text
2026-09-06 12:00:00
main
INFO
com.example.UserService
查询用户成功
```

这些信息能够帮助开发人员更加准确地定位程序运行情况。

# 20. 日志与普通控制台打印的核心区别

`System.out.println()` 更像是：

> 简单地把一段内容打印到控制台。

而专业日志技术提供的是：

> 一套完整的日志管理机制。

包括：

- Logger。
    
- 日志级别。
    
- 日志格式。
    
- 日志输出位置。
    
- 日志开关。
    
- 日志文件管理。
    

因此真正项目中更适合使用日志框架。

# 21. Spring Boot 中的日志

在 Spring Boot 项目中，Logback 相关依赖已经通过依赖关系提供，因此一般不需要再手动单独引入基础 Logback 依赖。

因此在 Spring Boot 项目中，可以比较方便地使用日志功能。

后续真正需要重点掌握的是：

- 如何获得 Logger。
    
- 如何使用 `debug`、`info` 等方法。
    
- 如何配置日志级别。
    
- 如何配置日志输出位置。

# 22. 日志框架解决的核心问题

可以把日志框架主要解决的问题概括为四个方面。

## 22.1 统一记录日志

不需要到处使用：

```java
System.out.println(...)
```

而是统一使用日志 API。

---

## 22.2 控制日志是否输出

日志可以根据配置决定：

> 哪些日志应该显示。

不需要通过删除 Java 代码控制。

---

## 22.3 控制日志输出位置

日志不仅可以输出到：控制台

还可以保存到：日志文件

---

## 22.4 提供更加完整的信息

日志不仅可以保存消息本身，还可以包含：

- 时间。
    
- 线程。
    
- 日志级别。
    
- 类名。
    

方便后续分析和排错。

# 23. 学习日志技术时要区分三个概念

## 23.1 日志

日志是：

> 程序运行过程中产生的记录信息。

---

## 23.2 日志门面

例如：

```text
SLF4J
```

负责：

> 给应用程序提供统一日志 API。

---

## 23.3 日志实现

例如：

```text
Logback
```

负责：

> 真正完成日志的记录、格式化和输出。

理解这三个层次后，就不会把：

```text
日志
SLF4J
Logback
```

混成同一个概念。
