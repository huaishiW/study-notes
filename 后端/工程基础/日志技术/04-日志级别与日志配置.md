# 1. 什么是日志级别

日志级别用于：

> 对不同重要程度的日志信息进行分类。

程序运行过程中产生的日志并不是同一种类型。

例如：

- 程序执行轨迹。
    
- 调试信息。
    
- 普通运行信息。
    
- 警告信息。
    
- 错误信息。
    

这些日志的重要程度不同，因此日志框架会通过不同级别进行区分。

常见日志级别按照优先级从低到高为：

```text
trace < debug < info < warn < error
```

也就是说：

```text
trace
```

优先级最低，

```text
error
```

优先级最高。

---

# 2. trace

`trace` 表示：

> 追踪级别。

主要用于记录非常详细的程序运行轨迹。

使用方式：

```java
log.trace("程序运行轨迹");
```

例如可以用于观察：

- 方法内部非常细致的执行过程。
    
- 程序经过了哪些步骤。
    
- 某些底层执行信息。
    

当前内容中指出：

> `trace` 使用较少。

因此在一般业务开发中，不会大量记录 `trace` 日志。

---

# 3. debug

`debug` 表示：

> 调试级别。

主要用于记录程序调试过程中的信息。

例如：

```java
log.debug("开始计算...");
```

或者：

```java
log.debug("结束计算...");
```

`debug` 经常用于帮助开发人员分析：

- 某段代码有没有执行。
    
- 某个方法执行到了哪个阶段。
    
- 程序执行过程是否符合预期。
    

当前内容中将 `debug` 视为实际开发中比较常用的较低日志级别。

---

# 4. info

`info` 表示：

> 一般信息级别。

用于记录程序运行过程中比较重要的正常事件。

例如：

```java
log.info("查询部门列表");
```

或者：

```java
log.info("根据id删除部门, id: {}", id);
```

`info` 一般用于记录：

- 业务操作开始。
    
- 关键业务事件。
    
- 网络连接。
    
- IO 操作。
    
- 一些重要程序状态。
    

因此：

> `info` 是实际业务开发中使用非常频繁的日志级别。

---

# 5. warn

`warn` 表示：

> 警告级别。

主要用于记录：

> 当前程序还可以继续运行，但是已经出现了值得关注的潜在问题。

使用方式：

```java
log.warn("...");
```

例如某些情况虽然暂时没有导致程序报错，但可能带来风险，就可以记录为：

```text
WARN
```

当前内容中将 `warn` 描述为：

> 记录潜在有害的情况。

---

# 6. error

`error` 表示：

> 错误级别。

用于记录程序中的错误信息。

使用方式：

```java
log.error("...");
```

例如程序发生异常或某个关键操作失败时，可以记录：

```text
ERROR
```

在当前几个常见日志级别中：

```text
error
```

优先级最高。

---

# 7. 日志级别的优先级

需要重点记住：

```text
trace < debug < info < warn < error
```

可以理解为：

|日志级别|主要含义|优先级|
|---|---|---|
|`trace`|详细运行轨迹|最低|
|`debug`|调试信息|较低|
|`info`|普通运行信息|中等|
|`warn`|警告信息|较高|
|`error`|错误信息|最高|

这里的“高低”主要用于决定：

> 在设置日志输出级别后，哪些日志可以被输出。

---

# 8. 为什么需要日志级别

如果程序中的所有日志无论重要程度都全部输出，可能产生大量日志信息。

例如：

```java
log.trace(...);
log.debug(...);
log.info(...);
log.warn(...);
log.error(...);
```

全部输出后，控制台或日志文件可能包含大量细节。

这会使真正重要的信息：

```text
WARN
ERROR
```

变得难以发现。

因此需要通过日志级别：

> 对日志进行筛选。

例如开发阶段可能希望看到更多：

```text
DEBUG
```

而程序运行时可能只希望关注：

```text
INFO
WARN
ERROR
```

等更重要的日志。

---

# 9. root level

在 Logback 中，可以通过：

```xml
<root level="...">
```

配置日志输出级别。

例如：

```xml
<root level="info">

    <appender-ref ref="STDOUT"/>

    <appender-ref ref="FILE"/>

</root>
```

这里：

```text
level="info"
```

表示：

> 当前日志输出的最低级别是 `info`。

---

# 10. 日志级别过滤规则

Logback 的核心过滤规则是：

> 只有大于等于当前配置级别的日志才会输出。

例如配置：

```xml
<root level="info">
```

日志优先级：

```text
trace < debug < info < warn < error
```

因此：

```java
log.trace("...");
log.debug("...");
```

不会输出。

```java
log.info("...");
log.warn("...");
log.error("...");
```

会输出。

所以：

```text
level="info"
```

实际上表示：

```text
输出 info、warn、error
```

---

# 11. level="debug"

如果配置：

```xml
<root level="debug">
```

那么根据：

```text
trace < debug < info < warn < error
```

会输出：

```text
debug
info
warn
error
```

而：

```text
trace
```

不会输出。

---

# 12. level="warn"

如果配置：

```xml
<root level="warn">
```

则只会输出：

```text
warn
error
```

而下面这些不会输出：

```text
trace
debug
info
```

因此：

> 配置级别越高，最终输出的日志数量通常越少。

---

# 13. level="error"

如果配置：

```xml
<root level="error">
```

则只会输出：

```text
error
```

日志。

例如：

```java
log.debug("调试");
log.info("普通信息");
log.warn("警告");
log.error("错误");
```

最终只有：

```java
log.error("错误");
```

对应的日志会被输出。

---

# 14. ALL

除了：

```text
trace
debug
info
warn
error
```

之外，Logback 配置中还可以看到：

```text
ALL
```

例如：

```xml
<root level="ALL">
```

当前内容中将：

```text
ALL
```

作为：

> 开启全部日志。

也就是说：

```text
trace
debug
info
warn
error
```

都可以输出。

---

# 15. OFF

与 `ALL` 相反的是：

```text
OFF
```

例如：

```xml
<root level="OFF">
```

表示：

> 关闭日志输出。

也就是说，即使代码中存在：

```java
log.info(...);
log.error(...);
```

日志配置为：

```text
OFF
```

后，也不会继续正常输出这些日志。

当前内容中将：

- `ALL`：开启日志。
    
- `OFF`：关闭日志。
    

作为日志开关配置。

---

# 16. ALL、OFF 与普通日志级别

可以这样理解：

```text
ALL
trace
debug
info
warn
error
OFF
```

其中：

- `ALL`：全部打开。
    
- `trace` ~ `error`：按照级别过滤。
    
- `OFF`：全部关闭。
    

因此：ALL 和 OFF

更接近日志输出的两个极端状态。

---

# 17. root 同时控制级别和输出位置

例如：

```xml
<root level="info">

    <appender-ref ref="STDOUT"/>

    <appender-ref ref="FILE"/>

</root>
```

这里同时包含两类信息。

第一：

```xml
level="info"
```

决定：

> 哪些级别的日志可以输出。

第二：

```xml
<appender-ref ref="STDOUT"/>
<appender-ref ref="FILE"/>
```

决定：

> 日志输出到哪里。

因此：

```text
root
```

既关联：

- 日志级别。
    

也关联：

- 日志输出目标。
    

---

# 18. 日志级别与 Appender 的区别

这两个概念不要混淆。

## 18.1 日志级别

回答的是：

> 哪些日志应该输出？

例如：

```text
INFO 以上
```

---

## 18.2 Appender

回答的是：

> 日志应该输出到哪里？

例如：

- 控制台。
    
- 文件。
    

所以：

```xml
<root level="info">
    <appender-ref ref="STDOUT"/>
    <appender-ref ref="FILE"/>
</root>
```

可以理解为：

> 把 `info` 及以上日志同时输出到控制台和文件。

---

# 19. 一个完整的日志级别示例

假设代码：

```java
log.trace("trace日志");
log.debug("debug日志");
log.info("info日志");
log.warn("warn日志");
log.error("error日志");
```

配置：

```xml
<root level="info">
    <appender-ref ref="STDOUT"/>
</root>
```

最终可以输出：

```text
info日志
warn日志
error日志
```

而：

```text
trace日志
debug日志
```

会被过滤掉。

这个例子体现了日志级别最核心的工作方式：

> 配置最低输出级别，再根据优先级进行过滤。

---

# 20. 为什么不能理解成“只输出指定级别”

这是一个容易出现的误区。

如果配置：

```xml
<root level="info">
```

并不是表示：

> 只输出 `info`。

而是表示：

> 输出 `info` 以及所有比 `info` 优先级更高的日志。

因此会输出：

```text
info
warn
error
```

而不会输出：

```text
trace
debug
```

---

# 21. 日志级别应该如何理解

可以把：

```xml
level="info"
```

理解成：

> 日志输出门槛。

优先级低于这个门槛的日志：

```text
trace
debug
```

会被过滤。

达到或超过门槛的：

```text
info
warn
error
```

才能继续输出。

因此：

> `level` 配置的是最低输出级别，而不是唯一输出级别。

---

# 22. 不同级别适合记录什么

## 22.1 trace

适合：

- 极其详细的运行轨迹。
    
- 底层执行过程。
    

当前使用较少。

---

## 22.2 debug

适合：

- 调试程序。
    
- 观察程序执行过程。
    
- 开发阶段分析问题。
    

---

## 22.3 info

适合：

- 业务正常运行信息。
    
- 关键业务操作。
    
- 关键事件。
    

例如：

```java
log.info("查询部门列表");
```

---

## 22.4 warn

适合：

- 潜在问题。
    
- 需要关注但暂时没有导致严重错误的情况。
    

---

## 22.5 error

适合：

- 错误信息。
    
- 程序运行中的严重异常情况。
    

---

# 23. 业务日志通常使用什么级别

当前部门管理示例中大量使用：

```java
log.info(...)
```

例如：

```java
log.info("查询部门列表");
```

```java
log.info("根据id删除部门, id: {}", id);
```

```java
log.info("新增部门, dept: {}", dept);
```

说明对于：

> 正常业务操作的关键事件

通常可以使用：

```text
info
```

级别记录。

# 24. 日志级别配置的意义

日志级别使我们可以：

> 不修改 Java 业务代码，就控制最终输出多少日志。

例如代码始终保留：

```java
log.debug("调试信息");
log.info("业务信息");
log.error("错误信息");
```

开发阶段可以配置：

```xml
<root level="debug">
```

获得更多日志。

如果只希望关注更重要的信息，可以提高配置级别。

也就是说：

> 日志代码负责记录什么，配置文件负责决定什么最终被输出。

---

# 25. 日志配置的基本思路

使用日志框架时，可以将配置问题拆成三个部分。

## 25.1 输出什么

由：

```text
日志级别
```

决定。

例如：

```xml
level="info"
```

---

## 25.2 输出到哪里

由：

```text
Appender
```

决定。

例如：

```text
STDOUT
FILE
```

---

## 25.3 以什么格式输出

由：

```text
Pattern
```

决定。

例如：

```text
时间 + 线程 + 级别 + 类名 + 日志正文
```

这三个问题共同构成日志配置的核心。

---

# 26. 常见误区

## 26.1 info 只输出 info

错误。

配置：

```xml
<root level="info">
```

实际输出：

```text
info
warn
error
```

因为：

> 大于等于配置级别的日志都会输出。

---

## 26.2 error 级别最低

错误。

当前常见日志级别从低到高是：

```text
trace < debug < info < warn < error
```

所以：

```text
error
```

优先级最高。

---

## 26.3 Appender 决定日志级别

错误。

Appender 主要决定：

> 日志输出到哪里。

日志级别主要通过：

```text
level
```

控制。

---

## 26.4 ALL 和 OFF 是普通业务日志类型

不应该这样理解。

它们主要用于配置：

- `ALL`：全部开启。
    
- `OFF`：全部关闭。
    

实际代码中常见记录方法仍然是：

```java
trace()
debug()
info()
warn()
error()
```

---

# 27. 学习重点

## 27.1 基础

需要掌握：

```text
trace < debug < info < warn < error
```

以及：

- `trace()` 的作用。
    
- `debug()` 的作用。
    
- `info()` 的作用。
    
- `warn()` 的作用。
    
- `error()` 的作用。
    

## 27.2 配置

需要掌握：

- `<root level="...">`
    
- `ALL`
    
- `OFF`
    
- 大于等于当前配置级别的日志才能输出。
    

## 27.3 重点

需要重点理解：

- 日志级别为什么存在。
    
- `level="info"` 为什么不只是输出 `info`。
    
- 日志级别和 Appender 的职责区别。
    
- 日志代码和日志配置为什么可以分离。
    
- `root` 如何同时关联日志级别和输出位置。
    

---

> [!tip] 一句话总结
> 
> Logback 常见日志级别按照优先级从低到高为 `trace < debug < info < warn < error`，`root` 中配置的 `level` 表示最低输出级别，只有大于等于该级别的日志才会输出；`ALL` 表示全部开启，`OFF` 表示全部关闭，而 Appender 则负责决定日志最终输出到控制台还是文件。
