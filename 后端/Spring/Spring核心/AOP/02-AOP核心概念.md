# 1. AOP 中为什么需要这些核心概念

在 Spring AOP 中，我们通常需要解决几个基本问题：

- 哪些方法可以被增强
    
- 要增加什么功能
    
- 哪些方法真正需要应用这些功能
    
- 公共功能和目标方法之间如何建立对应关系
    
- 最终被增强的是哪个对象
    

为了描述这些问题，Spring AOP 中引入了几个核心概念：

```text
JoinPoint
Advice
Pointcut
Aspect
Target
```

理解这些概念，是后续学习通知类型、切入点表达式和 AOP 案例的基础。

# 2. JoinPoint 连接点

## 2.1 什么是连接点

`JoinPoint` 中文称为：

**连接点**

材料中将连接点解释为：

> 可以被 AOP 控制的方法。

例如一个 Service 类中存在：

```java
public void save() {
}

public void delete() {
}

public List<Dept> list() {
}
```

这些方法都可能被 AOP 进行增强，因此都可以看作连接点。

## 2.2 连接点包含的信息

Spring AOP 中的 `JoinPoint` 不只是表示“某个方法”。

它还可以封装方法执行时的一些相关信息。

例如：

- 当前执行的方法
    
- 方法所在的目标对象
    
- 方法名称
    
- 方法参数
    

这些信息在后续记录操作日志时会非常重要。

材料中也明确说明，Spring AOP 提供的 `JoinPoint` 中封装了连接点方法执行时的相关信息。

# 3. Advice 通知

## 3.1 什么是通知

`Advice` 中文称为：

**通知**

它表示：

> AOP 中抽取出来的公共逻辑，也就是需要额外执行的功能。

最终通常表现为一个方法。

例如需要统计多个业务方法的执行耗时，那么公共逻辑可能包括：

```text
记录开始时间
执行原始方法
记录结束时间
计算方法耗时
```

这些重复逻辑被单独抽取出来后，就属于通知。

## 3.2 通知解决什么问题

通知主要回答的是：

> **需要给原始方法增加什么功能？**

例如：

- 记录日志
    
- 统计耗时
    
- 权限校验
    
- 事务处理
    

这些都可以作为通知中的公共功能。

# 4. Pointcut 切入点

## 4.1 什么是切入点

`Pointcut` 中文称为：

**切入点**

切入点表示：

> 匹配连接点的条件。

虽然很多方法都可以被 AOP 控制，但并不是所有方法都一定需要执行某个通知。

因此，还需要进一步确定：

> 哪些方法真正需要应用当前通知。

这就是切入点的作用。

## 4.2 连接点与切入点的区别

连接点表示：

> 可以被 AOP 控制的方法。

切入点表示：

> 当前通知真正需要匹配的方法。

例如，一个 Service 中有：

```java
save()
delete()
list()
update()
```

这几个方法都可以是连接点。

如果当前只希望对：

```java
list()
```

统计执行耗时，那么 `list()` 就是当前通知实际匹配到的切入点方法。

因此可以理解为：

```text
连接点范围更大
切入点是从连接点中筛选出来的一部分
```

# 5. 切入点表达式

在 Spring AOP 中，通常通过：

**切入点表达式**

来描述哪些方法属于切入点。

例如：

```java
execution(* com.huaishi.service.impl.DeptServiceImpl.*(..))
```

这类表达式用于匹配指定范围内的方法。

具体的 `execution` 和 `@annotation` 写法会在后续：

```text
execution切入点表达式.md
annotation切入点表达式.md
```

中单独整理。

当前阶段只需要理解：

> 切入点表达式负责描述“通知应该作用到哪些方法”。

# 6. Aspect 切面

## 6.1 什么是切面

`Aspect` 中文称为：

**切面**

切面用于描述：

> 通知与切入点之间的对应关系。

也就是说：

```text
通知 + 切入点 = 切面
```

通知负责说明：

> 要执行什么公共功能。

切入点负责说明：

> 这个功能要作用在哪些方法上。

两者组合之后，就形成了一个完整的切面。

## 6.2 切面描述的核心问题

一个切面实际上描述了三个信息：

- 对哪个方法进行增强
    
- 在什么位置执行增强逻辑
    
- 需要执行什么功能
    

例如：

```java
@Around("execution(* com.huaishi.service.impl.DeptServiceImpl.*(..))")
public Object recordTime(ProceedingJoinPoint pjp) throws Throwable {
    // ...
}
```

其中：

```java
execution(...)
```

描述需要增强哪些方法。

而：

```java
recordTime(...)
```

中的代码描述具体需要增加什么功能。

# 7. 切面类

包含切面的类称为：

**切面类**

在 Spring AOP 中，通常使用：

```java
@Aspect
```

标识当前类是一个切面类。

例如：

```java
@Component
@Aspect
public class RecordTimeAspect {
}
```

材料中明确指出，被 `@Aspect` 标识的类称为切面类。

# 8. Target 目标对象

`Target` 中文称为：

**目标对象**

它表示：

> 通知最终所应用的对象。

例如：

```java
@Service
public class DeptServiceImpl {
}
```

如果 AOP 中的通知最终应用到 `DeptServiceImpl` 的方法上，那么：

```text
DeptServiceImpl 对象
```

就是目标对象。

# 9. 几个核心概念之间的关系

可以这样理解这些概念：

`JoinPoint` 表示所有可能被 AOP 控制的方法。

`Pointcut` 用来从这些连接点中筛选出真正需要增强的方法。

`Advice` 表示要执行的公共增强逻辑。

`Aspect` 则负责把通知和切入点组合起来。

`Target` 是最终被增强的目标对象。

因此：

```text
连接点
表示哪些方法可以被增强

切入点
表示哪些方法实际要被增强

通知
表示要增加什么功能

切面
表示“对哪些方法增加什么功能”

目标对象
表示最终被增强的对象
```

# 10. Spring AOP 与动态代理

材料中进一步说明，Spring AOP 底层是基于：

**动态代理**

实现的。

程序运行时，Spring 会基于动态代理机制为目标对象生成对应的代理对象。

真正执行方法时，会通过代理对象对原始方法进行功能增强。

因此，Spring AOP 并不是直接修改目标对象中的原始方法代码，而是通过代理对象完成增强。

# 11. 当前阶段需要掌握的核心内容

1. `JoinPoint` 表示可以被 AOP 控制的方法。
    
2. `Advice` 表示抽取出来的公共功能，也就是通知。
    
3. `Pointcut` 表示匹配连接点的条件。
    
4. 切入点是从连接点中筛选出来的、真正需要应用通知的方法。
    
5. `Aspect` 表示通知与切入点之间的对应关系。
    
6. `@Aspect` 用于标识切面类。
    
7. `Target` 表示通知最终作用的目标对象。
    
8. Spring AOP 底层基于动态代理机制实现方法增强。
    
9. 可以用“对哪些方法增加什么功能”来理解切面的核心作用。
    

> [!tip] 一句话总结
> 
> `Spring AOP 中，JoinPoint 表示可被增强的方法，Pointcut 用于筛选实际需要增强的方法，Advice 表示增强逻辑，Aspect 将通知与切入点组合起来，而 Target 是最终被增强的目标对象。`
