# 1. 什么是 AOP

AOP 的全称是：

```text
Aspect Oriented Programming
```

中文通常称为：

**面向切面编程**，也称为**面向方面编程**。

当前阶段可以先将 AOP 理解为：

> **针对特定方法进行统一编程，在不修改原有业务代码的情况下，为这些方法增加额外功能。**

Spring 框架对 AOP 思想进行了实现，我们实际开发中学习和使用的主要是 **Spring AOP**。

# 2. 为什么需要 AOP

在实际项目中，经常会出现一些并不属于具体业务本身，但很多业务方法都需要执行的公共逻辑。

例如，需要统计项目中多个业务方法的执行耗时。

如果采用普通方式实现，需要在每一个业务方法执行前记录开始时间，在执行结束后记录结束时间，再计算两者之间的时间差。

如果项目中有大量业务方法需要统计耗时，那么相同的代码就需要在多个方法中重复编写。

这种实现方式会带来两个明显问题：

- 大量重复代码分散在不同业务方法中。
    
- 公共功能与原有业务逻辑混在一起，后续修改和维护比较麻烦。
    

AOP 的作用，就是把这些多个方法都需要执行的公共逻辑抽取出来统一处理。

# 3. AOP 解决问题的核心思路

以方法执行耗时统计为例，真正需要重复执行的公共逻辑包括：

- 方法执行前记录开始时间。
    
- 方法执行完成后记录结束时间。
    
- 根据开始时间和结束时间计算方法执行耗时。
    

这些代码和具体的部门查询、员工新增等业务本身没有直接关系。

使用 AOP 后，可以把这部分公共代码单独抽取出来，再统一应用到需要统计耗时的方法上。

这样就不需要在每个业务方法内部重复编写相同代码，也不需要为了增加耗时统计功能而修改原有业务方法。

因此，AOP 很适合处理：

> **多个方法都需要执行的重复性、通用性功能。**

# 4. AOP 的主要优势

## 4.1 减少重复代码

如果多个业务方法都需要执行相同功能，可以把这部分代码抽取到 AOP 程序中统一实现。

例如多个方法都需要：

```text
统计执行耗时
记录操作日志
进行权限控制
```

就不需要在每一个方法中重复编写对应代码。

---

## 4.2 对原有代码无侵入

使用 AOP 增强原有业务功能时，可以不修改原始业务方法。

也就是说，原来的业务代码仍然负责完成自己的业务逻辑，而额外的公共功能由 AOP 单独实现。

这种方式可以减少公共功能对业务代码的影响。

---

## 4.3 提高开发效率

公共逻辑只需要统一实现一次，然后应用到多个目标方法中。

相比在大量业务方法中重复编写相同代码，可以明显减少重复开发工作。

---

## 4.4 便于维护

如果公共逻辑需要修改，只需要修改 AOP 中统一抽取出来的实现，而不需要逐个修改所有业务方法。

因此，公共功能越多、涉及的方法越多，AOP 在维护方面的优势就越明显。

材料将 AOP 的优势概括为：

- 减少重复代码
    
- 代码无侵入
    
- 提高开发效率
    
- 维护方便
    

# 5. AOP 的常见应用场景

AOP 并不仅仅可以用于统计方法执行耗时。

在实际项目中，常见应用场景还包括以下几种。

## 5.1 操作日志

系统中很多新增、修改、删除操作都可能需要记录操作日志。

如果直接在每个业务方法中编写日志记录代码，会产生大量重复逻辑。

这类公共功能非常适合通过 AOP 统一实现。

---

## 5.2 权限控制

部分业务方法在执行之前，需要先判断当前用户是否具有对应权限。

这种需要在特定方法执行前统一进行判断的功能，也可以通过 AOP 实现。

---

## 5.3 事务管理

Spring 的事务管理也是 AOP 的典型应用场景。

例如使用：

```java
@Transactional
```

之后，可以在原始方法执行前进行事务相关处理，并在方法执行完成后根据执行结果进行提交或回滚。

因此，AOP 并不是一个只用于日志记录的技术，它可以用于处理多种横跨多个业务方法的公共功能。

# 6. AOP 与业务代码的职责划分

使用 AOP 后，可以让业务代码和公共功能各自承担更加明确的职责。

业务方法主要负责：

- 具体业务处理
    
- 数据计算
    
- 数据增删改查等业务逻辑
    

AOP 更适合负责：

- 方法耗时统计
    
- 操作日志
    
- 权限控制
    
- 事务等公共功能
    

这样可以避免大量与核心业务无关的代码混入业务方法中。

# 7. Spring AOP

AOP 本身是一种编程思想。

Spring 框架对这种思想进行了实现，因此在 Spring 项目中使用的通常是：

```text
Spring AOP
```

Spring AOP 可以针对满足特定条件的方法增加额外功能，而不需要直接修改这些方法原来的业务代码。

因此，学习 Spring AOP 的核心目标，就是掌握：

> **如何把公共功能统一抽取出来，并让这些功能作用到指定的方法上。**

# 8. 当前阶段需要掌握的核心内容

1. AOP 全称是 `Aspect Oriented Programming`，即面向切面编程。
    
2. AOP 可以用于针对特定方法统一增加额外功能。
    
3. AOP 适合处理多个业务方法中重复出现的公共逻辑。
    
4. 使用 AOP 可以减少重复代码，并避免直接修改原有业务方法。
    
5. AOP 的主要优势包括减少重复代码、代码无侵入、提高开发效率和便于维护。
    
6. 常见应用场景包括方法耗时统计、操作日志、权限控制和事务管理。
    
7. AOP 是一种思想，而 Spring AOP 是 Spring 对这种思想的实现。
    

> [!tip] 一句话总结
> 
> `AOP 是一种将多个方法共有的功能统一抽取并应用到指定方法上的编程思想，可以在不修改原有业务代码的情况下实现日志、权限、事务和耗时统计等功能。`
