# 1. 为什么会出现通知顺序问题

在实际项目中，可能会同时定义多个切面类。

如果这些切面类中的切入点都匹配到了同一个目标方法，那么当这个目标方法执行时，多个切面中的通知都会被触发。

此时就会产生一个问题：

> **这些通知到底哪个先执行，哪个后执行？**

材料中就是通过多个切面类同时匹配同一个目标方法，来说明通知执行顺序的问题。

# 2. 多个切面同时作用于一个方法

例如定义多个切面类：

```java
@Aspect
@Component
public class MyAspect2 {

    @Before("execution(* com.huaishi.service.*.*(..))")
    public void before() {
        log.info("MyAspect2 -> before ...");
    }

    @After("execution(* com.huaishi.service.*.*(..))")
    public void after() {
        log.info("MyAspect2 -> after ...");
    }
}
```

另外还有：

```java
@Aspect
@Component
public class MyAspect3 {
}
```

以及：

```java
@Aspect
@Component
public class MyAspect4 {
}
```

如果这些切面中的切入点都能够匹配同一个业务方法，那么目标方法执行时，这几个切面的通知都会执行。

# 3. 默认执行顺序

材料中说明，在不同切面类之间，如果没有额外指定顺序，通知的执行顺序默认与：

**切面类的类名字母排序**

有关。

例如：

```text
MyAspect2
MyAspect3
MyAspect4
```

按照类名字母顺序，`MyAspect2` 排在前面，`MyAspect4` 排在后面。

但是，目标方法执行前后的通知顺序并不完全相同。

# 4. 目标方法执行前的顺序

对于目标方法执行之前的通知：

> **类名字母排序越靠前，通知越先执行。**

例如：

```text
MyAspect2
MyAspect3
MyAspect4
```

那么前置通知的执行顺序就是：

```text
MyAspect2
MyAspect3
MyAspect4
```

也就是说，越靠前的切面越早进入。

材料中明确说明：

> 目标方法前的通知方法，类名字母排名靠前的先执行。

# 5. 目标方法执行后的顺序

对于目标方法执行之后的通知：

> **类名字母排序越靠前，反而越后执行。**

例如前置阶段进入顺序是：

```text
MyAspect2
MyAspect3
MyAspect4
```

那么目标方法执行完成之后，退出时会按照相反方向执行：

```text
MyAspect4
MyAspect3
MyAspect2
```

因此可以理解为：

```text
进入时：
外层切面先执行

退出时：
外层切面后执行
```

材料中对应的结论是：

> 目标方法后的通知方法，类名字母排名靠前的后执行。

# 6. 为什么默认顺序不适合长期依赖

虽然默认顺序和切面类名称有关，但实际开发中不应该通过修改类名来控制通知顺序。

例如为了调整执行顺序而把：

```text
MyAspect2
```

改成：

```text
AAspect
```

这种做法可读性很差，而且不方便维护。

材料中也指出，通过修改切面类名称来控制顺序比较繁琐，因此更推荐使用 Spring 提供的：

```java
@Order
```

注解。

# 7. @Order

`@Order` 用于：

> **控制不同切面类之间的执行顺序。**

例如：

```java
@Aspect
@Component
@Order(2)
public class MyAspect2 {
}
```

或者：

```java
@Aspect
@Component
@Order(1)
public class MyAspect4 {
}
```

通过给不同切面类设置不同的数字，就可以明确指定执行优先级。

# 8. @Order 数值越小优先级越高

它们的规则是：

> `@Order` 数值越小，优先级越高。

例如：

```java
@Order(1)
public class MyAspect4 {
}
```

```java
@Order(2)
public class MyAspect2 {
}
```

```java
@Order(3)
public class MyAspect3 {
}
```

那么目标方法执行前：

```text
MyAspect4
MyAspect2
MyAspect3
```

因为：

```text
1 < 2 < 3
```

数值越小的切面越先执行。

# 9. 目标方法前后的 @Order 规则

`@Order` 对目标方法前后的影响可以这样理解。

## 9.1 目标方法执行前

数值越小：

**越先执行**

例如：

```text
@Order(1)
@Order(2)
@Order(3)
```

执行顺序：

```text
1
2
3
```

## 9.2 目标方法执行后

数值越小：

**越后执行**

因此后置阶段的顺序会反过来：

```text
3
2
1
```

材料中的注释也明确写出了：

> 前置通知：数字越小先执行；后置通知：数字越小越后执行。

# 10. 如何理解这种前后顺序

可以把多个切面简单理解为一层一层包裹在目标方法外面。

例如：

```text
@Order(1)
@Order(2)
@Order(3)
目标方法
```

执行目标方法之前，会按照优先级从外向内进入。

目标方法执行结束后，再按照相反方向从内向外退出。

因此：

```text
目标方法前：
1 → 2 → 3

目标方法后：
3 → 2 → 1
```

这种理解可以帮助记忆 `@Order` 在前置和后置阶段的不同表现。

# 11. 默认顺序与 @Order 的区别

如果没有使用 `@Order`：

> 通知顺序默认受到切面类类名排序影响。

如果使用：

```java
@Order
```

则可以明确指定不同切面之间的执行优先级。

因此，实际需要控制通知执行顺序时，应优先使用：

```java
@Order
```

而不是依赖类名排序。

材料最后也将这一部分总结为两点：

1. 默认情况下，不同切面类的通知顺序与切面类名称排序有关。
    
2. 可以通过 `@Order` 控制不同切面类通知的执行顺序。
    

# 12. 当前阶段需要掌握的核心内容

1. 多个切面可以同时匹配并增强同一个目标方法。
    
2. 多个切面同时生效时，会产生通知执行顺序问题。
    
3. 默认情况下，不同切面类的执行顺序与切面类名称排序有关。
    
4. 目标方法执行前，排序靠前的切面通知先执行。
    
5. 目标方法执行后，排序靠前的切面通知后执行。
    
6. Spring 提供 `@Order` 用于主动控制不同切面类之间的顺序。
    
7. `@Order` 数值越小，优先级越高。
    
8. 目标方法执行前，`@Order` 数值越小越先执行。
    
9. 目标方法执行后，`@Order` 数值越小越后执行。
    
10. 实际开发中，应优先使用 `@Order` 明确控制顺序，而不是依赖切面类名称。
    

> [!tip] 一句话总结
> 
> `多个切面同时作用于同一个目标方法时，可以使用 @Order 控制执行顺序，其中数值越小优先级越高，目标方法执行前先执行，目标方法执行后则后执行。`
