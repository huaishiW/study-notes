当前观测到的可疑点如下：

Bochs 源码侧输出：

  5500000: f84e84c5 RIP=6684

我们自己的工程输出：

    
  5500000: bf3c01e2 RIP=6705

注意：这里不能直接断定 550 万就是“真实代码错误分叉点”。

原因是：当前已经进入设备越来越多的阶段，时钟中断、计数器、异步设备事件、设备初始化状态等因素，都可能导致 Bochs 源码侧和我们自己的工程侧在某个时间点发生路径漂移。此时出现 MD5/RIP 不一致，不一定表示指令实现错误，也不一定表示我们的代码逻辑必然有问题。

因此，550 万附近只能先作为“当前观测到的候选分叉点 / 可疑分叉区间”，需要进一步确认它到底是：

1. 时钟中断或动态事件导致的路径漂移；
    
2. 设备初始化状态不同导致的路径变化；
    
3. IO handler 或设备返回值不同导致的控制流变化；
    
4. 某段 Bochs 设备逻辑没有迁移；
    
5. 某个动态配置值被我们静态化时写错；
    
6. 某条指令、flag、寄存器或内存副作用实现不一致。
    

关于时钟影响的判断规则：

如果出现 MD5 或 RIP 对不上，尤其是 RIP 也开始不一致，不要立刻判断为代码错误。

必须优先重新运行 Bochs 源码侧，观察源码侧多次运行的结果是否一致。

判断方式如下：

1. 如果 Bochs 源码侧多次运行，在同一 step 附近输出的 MD5/RIP 不一致，说明该位置很可能受到时钟中断、计数器、动态设备事件或异步状态影响。
    
2. 这种情况下，当前不一致不一定是我们的代码错误。
    
3. 此时需要多次运行 Bochs 源码侧，尝试找到和我们工程输出一致或最接近的一条路径。
    
4. 如果 Bochs 源码侧多次运行结果稳定，而我们工程始终不同，才更倾向于认为是我们自己的工程缺少了某段 Bochs 逻辑，或者设备状态没有对齐。
    
5. 如果 Bochs 源码侧多次运行不稳定，则不要把第一个 MD5/RIP 不一致点直接当作真实 bug，应先分析是否是中断时机或动态状态造成的路径漂移。
    

RIP 和 MD5 的判断顺序：

1. 如果 RIP 一致，但 MD5 不一致：
    
    - 优先怀疑指令执行结果不一致；
        
    - 检查通用寄存器、flags、内存访问、IO 副作用、设备状态更新；
        
    - 这种情况更像是状态更新错误。
        
2. 如果 RIP 不一致：
    
    - 优先怀疑中断、设备事件、IO 返回值、设备初始化状态、控制流相关副作用；
        
    - 这种情况不一定是当前指令实现错了，可能是前面某个设备状态或中断时机已经不同；
        
    - 必须先重新运行 Bochs 源码侧，确认源码侧是否稳定。
        
3. 如果 MD5 和 RIP 都不一致：
    
    - 不要直接假设指令错误；
        
    - 优先确认 Bochs 源码侧多次运行是否一致；
        
    - 如果源码侧稳定，再回溯最近的设备、IO、中断路径；
        
    - 如果源码侧不稳定，则优先按时钟中断或动态事件处理。
