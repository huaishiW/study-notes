**软件工程**：是**将系统的、规范的、可度量的工程化方法**应用于软件开发、运行和维护的全过程

**软件工程的三要素**：
* **方法**：技术手段
* **工具**：软件开发工具或者集成环境、软件设计工具、软件测试工具、软件管理工具等
* **过程**：6 个阶段：计划、分析、设计、实现、测试、维护

# 1.1 软件的生存周期
## 1.1.1 可行性研究

要进行技术可行性、操作可行性、经济可行性、软件开发计划的研究。最后撰写《可行性报告》并制定《开发计划》

## 1.1.2 需求分析

要明确软件的功能、性能和运行环境约束等要求。最后撰写《需求规格说明书》、《测试准则》、《用户手册概要》

## 1.1.3 软件设计

这个阶段要进行概要设计（总体框架）和详细设计（过程、模块），并统一写到**软件设计报告**中。同时还要形成《数据库设计说明书》、《测试计划》初稿。

* **概要设计报告**：应说明功能分配、模块划分、程序的总体结构、输入输出以及接口设计、运行设计、数据结构设计和出错处理设计等
* **详细设计报告**：着重描述每一模块是怎样实现的，包括实现算法、逻辑流程等

## 1.1.4 软件构造

根据需求分析中开发环境和软件设计中的要求进行实际开发

## 1.1.5 测试

要进行功能测试、性能测试、压力测试、容量测试等等。完善测试计划和测试报告等

## 1.1.6 运维

软件交付后，根据需求或环境的变化，持续进行适当的修改。**如：纠错、需求变更、完善架构等**

# 1.2 软件设计的重要性

1. 是软件需求的直接体现（**用户界面设计**），综合考虑在需求、性能、运行环境等方面的要求。
2. 为软件构造提供依据，包括：**系统架构、关键算法、数据模型、并发、数据库访问机制、软件复用**等
3. 最终决定软件质量。通过良好的**分层和接口设计**提高可维护性和可移植性；通过**容错设计**提高可靠性；通过**高内聚、低耦合**实现灵活性、健壮性等
4. 及早发现软件设计中存在的错误，将极大减少软件修复和维护成本

# 1.3 软件设计要素

* **目标描述**：要解决的问题和将要达到的目标
* **设计约束**：软件开发的设计约束，例如：操作系统，浏览器约定、硬件设计等
* **产品描述**：对被设计的产品进行描述，例如：功能说明，性能描述等
* **设计原理**：表明问题可以通过该设计得到合理的解决，包括：科学原理、技术手段等
* **开发规划**：时间、人员、设备使用等
* **使用描述**：使用说明、操作序列，注意事项等

# 1.4 软件设计的基本思想
## 1.4.1 抽象

从众多的事物中抽取出共同的、本质性的特征，而不是舍弃非本质的特征。就是一个分离变与不变的过程

* **系统分析**
	- 需求目标 → 软件概念（名称）
	- 需求描述 → 功能模块 → 功能和接口定义

* **软件设计**
	- 处理流程 → 算法或活动
	- 数据对象（学生、教师、管理员） → 数据结构（用户和角色）

* **代码开发**
	- 类、函数名和形参表、变量名
	* **数据抽象**：把一个数据对象定义抽象成一个数据类型名
	* **过程抽象**：把完成一个特定功能的动作序列抽象成函数名和参数表，以后通过函数名和实际参数调用此过程

## 1.4.2 分解

是一种**自顶向下的设计策略**。对某个功能不断**分解完善**，逐步确立过程细节，直至该功能用程序语言描述的算法实现为止

**通过分解可以降低软件设计的复杂度**，将系统分割为几个相对简单的子系统以及子系统之间的关系。面向对象设计方法的设计过程就是**从概念模型到实现模型，且不断迭代的**

## 1.4.3 模块化和信息隐藏

模块化是指将软件分解为多个独立的模块（单元），不同的模块具有不同的功能和职责。每个模块可以独立开发和测试，最后组装成完整的软件。模块化是软件设计“逐步求精”过程的具体表现，是团队开发的必要条件

评价一个软件设计的模块化能力要从：
1. **模块可分解**：能否将模块分解为子问题，可降低系统的复杂性
2. **模块可组装**：能否复用已有的设计构件组装新的系统
3. **模块可理解**：模块能否作为一个独立单元理解（不用参考其他模块）
4. **模块连续性**：需求的微小变化只会导致单个模块的修改
5. **模块保护**：模块内部出现异常的时，它的影响只局限于模块内部

## 1.4.4 内聚与耦合

### 1.4.4.1 内聚性

模块内部关联程度的度量，**高内聚**是指一个软件模块是由相关性很强的代码组成，只负责一项任务，也就是常说的单一责任原则

### 1.4.4.2 耦合性

软件结构内**不同模块之间互连程度的度量，低耦合**是指模块与模块之间**接口简单，联系较少**

# 1.5 模块的划分方法及策略

1. 按**功能**划分模块，**遵循单一职责原则**，即模块功能要单一；
2. 根据功能特性多少，决定是否要划分子功能模块，但要**保证模块的完整性**，即模块分解后不应降低模块的独立性；
3. 模块内部，考虑**按层**划分模块（表现层、控制层、数据层）；
4. 新增的功能在新模块中实现，遵循**开闭原则**，即尽量减少对已有模块的改动；
5. **工具类或通用类**，包括业务逻辑，需要在项目内共用，要提出来做为单独的模块；
6. **模块间要信息隐藏**，模块接口尽可能少、且简单，遵循**最少知识原则**

>**信息隐藏**：指一个模块的开发者不必看到其它模块的内部，只需知道其接口即可；模块设计时，应将实现细节设置为不可访问

# 1.6 软件设计过程和活动

从工程管理的角度，软件设计可分为：
* **概要设计**：根据需求确定**软件**和**数据**的**总体框架**
* **详细设计**：进一步精化成软件的**算法表示**和**数据结构**

从技术上软件设计又包括若干个活动：

软件设计计划的步骤：
1. 确定设计的目标和验收标准
2. 明确目标软件系统应遵循的技术标准或规范
3. 重新审视项目风险管理计划
4. 制定本次设计过程的工作计划
5. 对设计过程的工作计划进行评审

## 1.6.1 软件体系结构设计

体系结构设计关注**软件整体架构和描述**，目标是建立软件系统的体系结构，也称“顶层框架”

明确定义软件**各子系统（模块）、关键构件、关键类的职责划分及协作关系**，同时也要描绘它们在物理运行环境下的**部署模型**，针对软件系统全局性、基础性的技术问题给出技术解决方案

## 1.6.2 用户界面设计

* 用户界面设计的目标：为用户使用目标软件提供友好的人机交互界面。

* 软件界面设计需要考虑的因素 ：适用于软件功能、易理解性、一致性、灵敏性、容错性、人性化、国际化、个性化、合理的布局、和谐的色彩

* 界面的设计内容：
	* **结构设计**（概念设计）
	* **交互设计**
	* **视觉设计**（色彩设计）

## 1.6.3 模块/子系统设计

* **子系统**：独立构成系统，不依赖其他子系统提供的服务
* **模块**：一个能提供一个或多个服务的系统部件。它能利用其它模块提供的服务，一般不被看成一个独立的系统
* 由于模块和子系统都是软件组成部分，相互之间存在接口，其设计方法有很多类似的方面，因此我们统一称为模块设计
* **模块设计的内容**：
	* 确定模块的具体接口定义
	* 设计模块内部结构（更小粒度的模块、构件、类），明确它们之间的关系确保他们能够协同完成高层模块接口规定的所有功能和行为

## 1.6.4 数据模型设计

在很多软件系统中，**数据是其核心**。因此，对数据元素的**格式、结构、访存、表示**等机制进行良好建模和优化，是提高软件设计质量和系统性能的基础，对软件系统的应用具有重要意义

* **数据模型设计**是数据结构设计、数据库设计、甚至数据文件设计等的统称

## 1.6.5 过程/算法设计

对模块内部的工作和执行过程进行描述，给出有关处理的精确说明，例如事件的顺序、确切的决策位置、循环操作以及数据的组成等

# 1.7 软件设计的思路

1. **由顶向下**：先设计软件用户界面，由此推导软件的实现方法
2. **由底向上**：先设计数据库再搭建软件的逻辑和界面

# 1.8 软件设计质量

要从以下几个方面去考虑软件设计的质量：结构良好、充分性、可行性、简单性、实用性、灵活性、健壮性、可移植性、可复用性、标准化
